# PROFIT PATH 缓存与行情表格精简

这是此前一小时窗口版本的验证记录；后续 48 小时设计与 v2 缓存见 [48 小时口径](profit-path-48h-2026-10-14.md)。

## 本次行为

- 页面加载即恢复浏览器上次有效 PROFIT PATH 展示，随后查询最新分钟历史。整块缓存标明样本时间与“旧值”，不混入新成本数字。
- 缓存保存在当前站点的 localStorage，以最新分钟样本时间计最多 15 分钟；保存时间更新不能延长旧样本寿命。只保存公开指标的展示文本、表格数值和原始倍数提示，不保存钱包、凭据或手动下单方案。
- 无缓存时先显示“正在读取历史”，避免把请求尚未完成误报为样本不足。真实缺失、请求失败、缓存过期均明确显示。
- 两小时分钟历史单独并行加载，PROFIT PATH 无需等待 24 小时曲线或辅助状态接口。有效结果约每分钟保存一次；损坏、存储被禁用或配额不足时仍可使用在线数据。
- 用户确认移除 MARKET SNAPSHOT 页面表格。底层 BTC/ETH BBO、HL 订单簿、资金费及历史字段继续采集，成本模型不变。

## 验证

55 项 Node 测试通过，包括缓存跨刷新、超期/未来时间拒绝、损坏内容与存储失败、辅助表格不可用时仍保留有效核心指标。语法检查、资产构建、Worker dry-run 通过。

浏览器使用明确标注的独立合成历史测试页：首次无缓存显示加载；取得有效结果后，模拟历史 HTTP 503，再次打开和刷新仍显示原数值，并标注历史缓存和失败。HL 行删除线保留。合成数据没有写入 D1 或真实本地历史数据库，测试服务已停止。

真实本地预览显示有效分钟窗口，市场表格已移除。

用户随后批准部署，版本 `3f01ce33-1706-4afb-a8ef-c66759f92073` 已发布到现有 Cloudflare Worker。六个静态资产中新增缓存模块并更新页面/应用脚本，两个 Cron 保持原配置，无数据库迁移。生产页面已确认市场表格移除，并显示历史加载状态及样本时间。核查时生产恢复后的分钟窗口仍不足 48 分钟，尚无有效 60 分钟指标可用于首次缓存；本地从 15:52 开始的连续窗口已有效。缓存不能消除这种真实的数据不足。本次未提交或推送 GitHub。

## 发布与恢复

本补丁只更新静态网页及本地服务的模块白名单，无新数据库迁移、Cron 或账户权限变更。部署后首次访问没有有效缓存仍需在线历史结果；缓存不能修复采集缺口。回滚网页到上一版本即可恢复旧展示，新 localStorage 项不会被旧页面使用。
